# pull-request-discussion

## 禁止事項

- いかなる場合でもpushすることを禁止
- 検討段階でコミットすることを禁止
- ドキュメント関連のmarkdownファイルをコミットすることを禁止
- ユーザーに確認せずPRを作成することを禁止
- ユーザーに確認せず、またこのスキルで定義されている以外のタイミングや内容でPRに返信することを禁止
- コミットのco-autherにclaudeを使用したことがわかるような記載を残すことを禁止

## 概要

GitHubのプルリクエストのレビューコメントをもとに、どのように対応するのが良いかを考えるスキルです。
ユーザーが対応方針を決定するまで、徹底的にユーザーにヒアリングを行い、必要に応じてコメントの内容を整理したり、対応の選択肢を提示したりします。

## 手順

### 対応方針が明確なもの

```
<対応済みなら✅ | 未対応なら🔲> #: <通し番号> \[[link](<そのコメントへのURL>)\]
指摘者: <指摘したユーザー名>
ファイル名: <対象のファイルパス>
原文: <要約していない指摘内容の原文>
要約: <要約した指摘内容>
対応方針: <対応方針>
────────────────────────────────────────
```

### 対応方針が複数考えられるもの

```
<対応済みなら✅ | 未対応なら🔲> #: <通し番号> \[[link](<そのコメントへのURL>)\]
指摘者: <指摘したユーザー名>
ファイル名: <対象のファイルパス>
原文: <要約していない指摘内容の原文>
要約: <要約した指摘内容>
対応方針 1: <対応方針>
対応方針 2: <対応方針>
対応方針 3: <対応方針>
(以下対応方針が考えられるだけ続く)
────────────────────────────────────────
```

### 対応する必要がないと考えられるもの

```
<対応済みなら✅ | 未対応なら🔲> #: <通し番号> \[[link](<そのコメントへのURL>)\]
指摘者: <指摘したユーザー名>
ファイル名: <対象のファイルパス>
原文: <要約していない指摘内容の原文>
要約: <要約した指摘内容>
対応が不要な理由: <なぜ不明だと考えられるのか>
────────────────────────────────────────
```

### 情報収集

1. 現在のブランチで作成されているプルリクエストを特定する
2. ghコマンドを用いて、そのプルリクエストのレビューコメントを全て取得する
3. 取得したコメントを内容ごとにグルーピングする
  a. 対応方針が明確で、議論の余地がないもの
  b. 対応方針が複数考えられ、ユーザーの判断を要するもの
  c. 対応する必要がないと考えられるもの
4. グルーピングしたコメントをテンプレート通りにまとめて、プロジェクトルートに ./pr_review_comments.md というファイル名で保存する
  a. 順番は対応方針が「明確なもの→対応方針が複数考えられるもの→対応する必要がないと考えられるもの」
  b. このファイルは絶対にpushしてはいけません

### ユーザーの入力があったら

1. ユーザーが指定した番号のコメントについて、冗長で詳細に、詳しく解説する
2. ユーザーが指定した番号のコメントについて、考えられる対応方針を複数提示する
3. ユーザーが指定した番号のコメントについて、ユーザーが選択した対応方針を実行するために必要なタスクを洗い出す

### 実装フェーズ

1. ユーザーからの入力に基づいて、必要なタスクを実行する
2. 修正したファイルをコミットする
  a. コミットメッセージには「PR-0001」のような、pr_review_comments.mdのコメント番号の痕跡を残すことは禁止
  b. コミットのco-autherにclaudeを使用したことがわかるような記載を残すことは禁止
3. 修正が一通り完了したら、./pr_review_comments.md の当該タスクに✅をつける
  a. このファイルは絶対にpushしてはいけません


### 最後に

1．情報収集で得た情報を再度提示する
2. ユーザーの入力を待つ
