# tsukimi-super-auto-with-commit-with-pr

# 概要

tsumikiを用いて、機能開発の要件定義、設計、タスク分解、ループを自動化するスキルです。さらに、生成された書類やコードをコミットし、PRの作成まで行います。
途中で実行を止めることなく、最後まで全自動で機能開発を行います。

## 手順

1. まず今のgitの状態を確認し、アンステージや未コミットの変更があればこのスキルの実行を中止しユーザーに伝え、解消を促す。
2. ユーザーが入力した内容をもとに、求めている機能開発の概要を作成する。
  - このとき不明点や漠然としている点は、徹底的にユーザーにヒアリングを繰り返し、十分な情報が集まるまで続ける。
3. /tsumiki:kairo-requirements コマンドを実行し、機能開発の要件定義を行う。
4. 作業ブランチをユーザーに尋ねる 選択肢は以下
  - 現在いるブランチを使用する
  - 要件定義の内容をもとに、その名前を用いてブランチを作成
5. /tsumiki:kairo-requirements が完了したタイミングで、生成された書類をすべてコミットする。
6. 作られた要件定義書の「赤信号」「黄色信号」を順番にユーザーにヒアリングし、書類の確度をあげる。
7. 書類の確度が十分に高まったタイミングで、生成された書類をすべてコミットする。
8. /tsumiki:kairo-design <要件名> コマンドを実行し、機能開発の設計を行う。
9. 作られた設計書の「赤信号」「黄色信号」を順番にユーザーにヒアリングし、書類の確度をあげる。
10. 書類の確度が十分に高まったタイミングで、生成された書類をすべてコミットする。
11. /tsumiki:kairo-tasks <要件名> コマンドを実行し、機能開発のタスク分解を行う。
12. 作られたタスク分解書を全てコミットする。
13. /tsumiki:kairo-loop <要件名> <開始TASK-ID (TASK-****)> <終了TASK-ID (TASK-****)> コマンドを実行し、機能開発のループを開始する。
  - このとき、各タスクを実装し終わった際にコミットすること。
14. ループが完了したタイミングで、生成されたコードが全てコミットされていることを確認する。
15. コードが全てコミットされていることを確認したら、PRを作成する。
  - PRの本文には、ユーザーが入力した内容をもとに作成した機能開発の概要と、要件定義書、設計書、タスク分解書へのリンクを記載する。
16. PRを作成したら、ユーザーにPRのURLを伝える。
