# tsukimi-super-auto

# 禁止事項

- いかなる場合でもpushすることを禁止
- ドキュメントファイルをコミットすることを禁止
- tsumiki生成したmarkdownファイルをコミットすることを禁止
- ユーザーに確認せずにPRを作成することを禁止
- git/github上から追跡できる内容をコミット/公開することを禁止
- コードのコメントにtsukimiで用いられる(TASK-****)のような痕跡を残すことを禁止
- コミットメッセージにtsukimiで用いられる(TASK-****)のような痕跡を残すことを禁止

# 概要

tsumikiを用いて、機能開発の要件定義、設計、タスク分解、ループを自動化するスキルです。さらに、生成された書類やコードをコミットし、PRの作成まで行います。
途中で実行を止めることなく、最後まで全自動で機能開発を行います。

## 手順

1. まず今のgitの状態を確認し、アンステージや未コミットの変更があればこのスキルの実行を中止しユーザーに伝え、解消を促す。
2. ユーザーが入力した内容をもとに、求めている機能開発の概要を作成する。
  - このとき不明点や漠然としている点は、徹底的にユーザーにヒアリングを繰り返し、十分な情報が集まるまで続ける。
3. /tsumiki:kairo-requirements コマンドを実行し、機能開発の要件定義を行う。
4. 要件定義の内容をもとに、その名前を用いてブランチを作成する。
5. 作られた要件定義書の「赤信号」「黄色信号」を順番にユーザーにヒアリングし、書類の確度をあげる。
6. /tsumiki:kairo-design <要件名> コマンドを実行し、機能開発の設計を行う。
7. 作られた設計書の「赤信号」「黄色信号」を順番にユーザーにヒアリングし、書類の確度をあげる。
8. /tsumiki:kairo-tasks <要件名> コマンドを実行し、機能開発のタスク分解を行う。
10. /tsumiki:kairo-loop <要件名> <開始TASK-ID (TASK-****)> <終了TASK-ID (TASK-****)> コマンドを実行し、機能開発のループを開始する。
  - これらのタスク一つごとにコミットを行う
  - pushは禁止 決して行わない
  - コミットメッセージに「TASK-0001」のようなtsumikiの痕跡を残すことは禁止
11. ループが完了したら、実装内容をユーザーに提示する。
12. ユーザーにPRを作成する際、何をタイトルや概要に記載するのがよいか提示する。
